# Navigation and first-run implementation plan

> Execute inline with superpowers:executing-plans; authorization and design
> choices are recorded below.

**Goal:** Make project navigation recoverable and legible, and first-run project
creation fit the desktop environment.

**Architecture:** Reuse existing selected-project resolution and navigation
callbacks. Render project choices as DropdownMenu links with native modified
click behavior. Derive section breadcrumbs in the shared project header; hide
empty first-run navigation in the app layout rather than the sidebar itself.

**Tech stack:** React, React Router, Radix DropdownMenu, Vitest, Storybook.

**Spec:**
[Issue #2936](https://github.com/purplefish-ai/factory-factory/issues/2936) and
the constraints and decisions below.

## Constraints and decisions

- Node 26.12.1 and pnpm 12.15.0; preserve URLs and existing callback behavior.
- No central router, app-sidebar, settings docs, or Kanban changes.
- Empty means a loaded empty project list; pending/error must retain navigation.
- Electron defaults Local Path; web continues to default GitHub URL.
- DropdownMenu uses links rather than action-only items, preserving native
  modified/middle click and copy-link behavior. Retry remains an action.
- Shared project headers show Board, Agents, or Reviews. Workspace detail keeps
  its existing workspace breadcrumb; settings owns its own breadcrumb.
- Alternative: patch Select sentinel handling. Rejected because command actions
  and navigation links are menu semantics, not selection form controls.

## Review focus

- Deleted/archived stored project falls back to an active project.
- NOT_FOUND provides Go to projects; transport failure still offers Retry.
- Modified project clicks do not change the current tab's selected project.
- Menu keyboard/typeahead must not trigger review page shortcuts.
- First-run hiding must not persist a closed sidebar preference or hide errors.
