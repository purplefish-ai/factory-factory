# Board and sidebar consistency (#2936)

## Design and defaults

Keep Todo, Working, Waiting, Done in both surfaces. Todo rows open the same
lazily loaded issue launch sheet, with a separate external issue link. The issue
hook exposes loading, disconnected, error and ready state; both surfaces show
retry/configuration actions. The first board without workspaces offers creation
without hiding issues.

Board filtering searches workspace names, branch names and summaries, and issue
titles/IDs. Sorting is client-side: newest created remains the default outside
Waiting; Waiting defaults to oldest known observed waiting entry, unknown last.
The server snapshot owner records optional `waitingSince` only after accepted
state transitions into Waiting. It preserves the value for same-status refresh,
ignores stale updates and clears it on exit. Initial Waiting hydration and
server restart stay unknown, without substituting creation/activity timestamps.
No schema/migration is necessary. Considered persisted waiting intervals,
deferred because their restart/race semantics require a separate lifecycle
contract.

This implements the board slice of
[#2936](https://github.com/purplefish-ai/factory-factory/issues/2936).

Selection is explicit through card checkboxes. Archive selected uses the
existing archive command, confirmation, cache suppression, Git-lock recovery and
partial failure handling. Successful IDs clear; failures remain selected and
visible.
