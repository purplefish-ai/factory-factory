# Settings navigation implementation plan

**Goal:** Give settings cohesive, bookmarkable sections and explicit project
ownership.

**Architecture:** Keep `/admin` as General, with URL navigation to Workspace,
Integrations, Appearance, Voice, System, and Server logs. Compose existing
cards; only System mounts diagnostics polling. Project cards consume one
route-selected project and never write selected-project storage. Legacy
`/admin/project` lists links to scoped settings. `/logs` remains an alias.

**Tech stack:** React, React Router, tRPC, Vitest, Storybook.

**Spec:**
[Issue #2936](https://github.com/purplefish-ai/factory-factory/issues/2936),
with the authorized settings decisions and constraints recorded below.

## Constraints and choices

- Preserve existing provider behavior and backend interfaces.
- Toggles/selects autosave; text and credentials require explicit submission.
- General: notifications, IDE, chat defaults. Workspace: child workspaces,
  ticket dispatch, PR review. Integrations: Codex, CLI auth, Slack. System:
  stats, processes, environment, app information, backup, worktree cleanup.
- Prefer route links over tabs: browser history and direct URLs work without
  duplicating router state. Keep a reachable project directory rather than
  silently choosing or changing the globally selected project.
- Failed independent queries retain the shell and provide their existing Retry.
- Project configuration failure must never show or edit another project.
- Credentials retain drafts on save failure; prerequisite validation/team choice
  remains part of explicit credential submission.

## Review focus

Direct unknown settings sections recover to General. Slow or failed diagnostics
cannot block General or navigation. Unknown project slugs cannot fall back to
the first project. Switching project URLs remounts project-owned forms. Custom
IDE save failures preserve the entered command and remain retryable.
