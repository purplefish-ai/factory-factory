# State Ownership Matrix

Status: implemented

This document defines single-writer ownership for high-risk persisted state.
Each field group should have one canonical writer service/module.

## Workspace field ownership

| Field group | Canonical writer |
| --- | --- |
| `status`, `init*` (except `initScriptPid`) | `workspaceStateMachine` / workspace lifecycle services |
| `initScriptPid` | `workspaceStateMachine` / workspace lifecycle services (clears on transitions); startup script service (`src/backend/services/run-script/service/startup-script.service.ts`) sets and clears during script execution |
| `branchName` (correction when the PR is on a different branch) | `PRSnapshotService` (`src/backend/services/github/service/pr-snapshot.service.ts`) |
| `worktreePath`, `branchName`, `isAutoGeneratedBranch` | workspace init/worktree lifecycle orchestration; `PRSnapshotService` also corrects `branchName` when PR is on a different branch |

## WorkspacePR field ownership

The PR cache's thirteen fields used to sit on `Workspace` and appear in the table
above, written by four different services. They now live in their own 1:1
`WorkspacePR` row, written only by
`src/backend/services/workspace/resources/workspace-pr.accessor.ts`.

As with `WorkspaceRatchet` below, there is no lint rule for them because there no
longer needs to be: the columns are absent from `Workspace`, so nothing else can
name them.

| Field | Was |
| --- | --- |
| `url` | `Workspace.prUrl` |
| `number` | `Workspace.prNumber` |
| `state` | `Workspace.prState` |
| `reviewState` | `Workspace.prReviewState` |
| `ciStatus` | `Workspace.prCiStatus` |
| `syncedAt` | `Workspace.prUpdatedAt` (renamed; it always held the caller's observation time, never GitHub's PR `updated_at`) |
| `discoveryLastCheckedAt` | `Workspace.prDiscoveryLastCheckedAt` |
| `discoveryRetryCount` | `Workspace.prDiscoveryRetryCount` |
| `discoveryNextCheckAt` | `Workspace.prDiscoveryNextCheckAt` |
| `ciFailedAt` | `Workspace.prCiFailedAt` |
| `ciLastNotifiedAt` | `Workspace.prCiLastNotifiedAt` |
| `reviewLastCheckedAt` | `Workspace.prReviewLastCheckedAt` |
| `reviewLastCommentId` | `Workspace.prReviewLastCommentId` |

Reads flatten back to the old `pr*` names at the accessor boundary
(`flattenWorkspacePR`), so derived state, the snapshot stream, the v4 export
format and the client are unchanged by the split.

Two writes span this table and `Workspace`, and both take a transaction:
correcting a branch name alongside a PR refresh
(`recordPrSnapshotWithBranchName`, `applyPrSnapshotWithDispatchReset`), and
clearing the discovery schedule when a branch is renamed
(`setBranchNameAndClearDiscoverySchedule`).

There is no lint rule for the individual fields because there no longer needs to

## WorkspaceRunScript field ownership

The run-script group's seven fields used to sit on `Workspace` and appear in the
table above. They now live in their own 1:1 `WorkspaceRunScript` row, written only
by `src/backend/services/workspace/resources/workspace-run-script.accessor.ts`,
and policed the same way `WorkspacePR` and `WorkspaceRatchet` are — by
`OWNED_SIDE_TABLES` rather than by per-field lint entries.

| Field | Was |
| --- | --- |
| `command` | `Workspace.runScriptCommand` |
| `postRunCommand` | `Workspace.runScriptPostRunCommand` |
| `cleanupCommand` | `Workspace.runScriptCleanupCommand` |
| `pid` | `Workspace.runScriptPid` |
| `port` | `Workspace.runScriptPort` |
| `startedAt` | `Workspace.runScriptStartedAt` |
| `status` | `Workspace.runScriptStatus` |

Reads flatten back to the old `runScript*` names at the accessor boundary
(`flattenWorkspaceRunScript`), so derived state, the snapshot stream, the v4 export
format and the client are unchanged by the split.

Two concerns share the row. The first three columns are a cache of the worktree's
`factory-factory.json`; the last four describe a live process. They share a row
because they share a writer — the pre-split table above listed two different
canonical writers for them, but both went through
`workspace-run-script.service.ts`, and one of the three config entries also named
`workspace-query.service.ts`, which had stopped writing them. A stale owner entry
is invisible to a lint rule that only checks whether a writer is *permitted*.

The config group stays a cache rather than becoming a projection like the kanban
column and `RatchetState`, because its source of truth is a file rather than
another column: deriving it on read would mean a filesystem call per workspace per
list query. `reconcileWorkspaceCommandCache` repairs drift at the point of use
instead, re-reading the file before a script starts or stops.

These writes no longer touch `Workspace.updatedAt`, the same consequence the PR
cache split had: `@updatedAt` only fires for the table being written. Starting or
stopping a run script therefore no longer floats its workspace up the sidebar and
board, which order by `updatedAt`. Deliberate — a process exiting was never
workspace activity, the activity the UI displays (`lastActivityAt`) comes from
session timestamps, and it stops a busy run script from keeping `updatedAt` fresh
enough to defer the stale-`ARCHIVING` recovery sweep.

The runtime group is persisted even though a restart invalidates the process it
describes, because `pid` is the only handle on an orphan — run scripts spawn with
`detached: false`, so they normally die with the server, but a SIGKILL or crash
leaves them behind and `verifyRunning` finds them with `process.kill(pid, 0)`.
Only `STARTING` and `STOPPING` are cleared at startup, by
`resetStaleTransientStatuses`.

## RatchetState has no owner

`ratchetState` is absent from the table above because it is not stored. It is a
projection of the PR observation, computed by `deriveRatchetState`
(`src/shared/core/ratchet-state.ts`) at the accessor boundary that flattens the
side tables, so every read gets it and no write can put it out of step with the
PR cache.

| Input | Source |
| --- | --- |
| `ratchetEnabled` | `WorkspaceRatchet.enabled` |
| `prState` | `WorkspacePR.state` |
| `prCiStatus` | `WorkspacePR.ciStatus` |
| `prReviewState` | `WorkspacePR.reviewState` (GitHub's raw `reviewDecision`) |
| `prHasMergeConflict` | `WorkspacePR.hasMergeConflict` |

The last of those is new. A merge conflict was observed on every ratchet fetch but
never persisted as a fact: the ratchet folded it straight into
`RatchetState.MERGE_CONFLICT` and stored that, so a restart could not tell "no
conflict" from "a conflict we had already folded in". The projection replaced one
derived enum column with one observed boolean.

`RatchetState` stays declared in `prisma/schema.prisma` even though no model uses
it, so `src/shared/core/enums.ts` keeps a schema-side pair for the drift test, and
because it is still the vocabulary the snapshot stream and the v4 export format
speak. The v4 format requires `ratchetState`, so the export computes it on the way
out; on the way in it is read only to recover `hasMergeConflict` from a backup file
that predates the column.

## WorkspaceAutoIteration field ownership

The auto-iteration group's five fields used to sit on `Workspace` and appear in
the table above. They now live in their own 1:1 `WorkspaceAutoIteration` row,
written only by
`src/backend/services/workspace/resources/workspace-auto-iteration.accessor.ts`,
and policed by `OWNED_SIDE_TABLES` rather than by per-field lint entries.

| Field | Was |
| --- | --- |
| `mode` | `Workspace.mode` |
| `status` | `Workspace.autoIterationStatus` |
| `config` | `Workspace.autoIterationConfig` |
| `progress` | `Workspace.autoIterationProgress` |
| `sessionId` | `Workspace.autoIterationSessionId` |

Reads flatten back to the old flat names at the accessor boundary
(`flattenWorkspaceAutoIteration`), so the workspace list, the v4 export format and
the client are unchanged by the split.

`mode` travelled with the group rather than staying on `Workspace`. It reads like
a general workspace attribute, and the pre-split ownership table listed it
separately from the four `autoIteration*` fields, but every consumer of it is an
auto-iteration consumer: the kanban card gates its badge on it, the right panel
and the progress banner derive `isAutoIteration` from it, creation only validates
it against `autoIterationConfig`, and `auto-iteration.trpc.ts` uses it as an entry
guard. It is the group's discriminant — the same call the ratchet split made for
`ratchetEnabled`.

Unlike the three splits before it, none of these fields are on the snapshot wire:
the client's snapshot adapter lists all five under `mutationOnlyFieldDefaults`,
because they change through explicit mutations rather than live activity. Only
`mode` and `config` are in the v4 export format, both already optional with
defaults — `status`, `progress` and `sessionId` describe a loop that does not
survive an export, so a workspace whose loop was running when the backup was taken
restores idle rather than half-resumed.

Same `updatedAt` consequence as the three splits before it: these writes no longer
touch `Workspace.updatedAt`, so loop progress does not float its workspace up the
sidebar and board.

## Enforcement

- `scripts/check-single-writer.mjs` enforces these ownership boundaries for write calls.
- Ownership checks apply to `workspaceAccessor` mutation APIs that write via `update`/`updateMany`, including wrapper mutators (for example `transitionWithCas` and `registerInitializedWorktree`).
- `WorkspacePR`, `WorkspaceRatchet`, `WorkspaceRunScript` and `WorkspaceAutoIteration` need no per-field entries there: their single writers are schema facts, not lint rules. The `OWNED_SIDE_TABLES` rule keeps each table's writes in one file.
- `pnpm check:ownership` should run in CI.
